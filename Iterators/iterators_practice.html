SET 01

Basics and laziness

Before the adapters: what an iterator actually is, and the three ways to get one.

1.1easy Drive an iterator by hand

Task

From [1, 2, 3], call .next() four times and collect what comes back. Predict the fourth before running.

Fourth call returns

Solution
Answer
let v = vec![1, 2, 3];
let mut it = v.iter();

it.next();   // Some(1)
it.next();   // Some(2)
it.next();   // Some(3)
it.next();   // None    — and stays None forever
Why it must be mut

next() takes &mut self — it advances an internal position. The iterator carries state even though v itself never changes.

1.2easy Laziness in action

Task

Write v.iter().map(|x| x * 2); on its own line and compile it. What does the compiler say? Then make it actually produce [2, 4, 6].

Solution
warning: unused `Map` that must be used
  = note: iterators are lazy and do nothing unless consumed
The fix
fn doubled(v: &[i32]) -> Vec<i32> {
    v.iter().map(|x| x * 2).collect()
}
// [2, 4, 6]

Memorise that warning text. Adapters build a description; only a consumer runs it.

1.3easy Sum without a loop

Task

Total a slice of i32.

Solution
Answer
fn total(v: &[i32]) -> i32 {
    v.iter().sum()
}
// [1,2,3] -> 6

The return type tells sum() what to build. Standing alone you would need .sum::<i32>().

1.4med Modify in place

Task

Add 100 to every element of a vector, in place. Which of the three iterators do you need?

Solution
Answer
fn bump_all(v: &mut Vec<i32>) {
    for x in v.iter_mut() {
        *x += 100;      // the * reaches through &mut i32
    }
}
// [1,2,3] -> [101, 102, 103]

.iter() would give read-only &i32; .into_iter() would consume the vector. iter_mut is the only one that lets you write through.

1.5med Consume to avoid cloning

Task

Take a Vec<String> by value and return them uppercased — with no .clone() anywhere.

Solution
Answer
fn shout(v: Vec<String>) -> Vec<String> {
    v.into_iter().map(|s| s.to_uppercase()).collect()
}
// ["ada", "ravi"] -> ["ADA", "RAVI"]
This is when into_iter is right

Each String is moved out — no allocation, no clone. With .iter() you would get &String and need to clone to own the result. Taking by value signals "I am finished with this".

SET 02

map and filter

The two you will use most — and the reference levels that trip everyone up.

2.1easy Square everything

Task

Return every element squared, leaving the input alone.

Solution
Answer
fn squares(v: &[i32]) -> Vec<i32> {
    v.iter().map(|x| x * x).collect()
}
// (1..=10) -> [1, 4, 9, 16, 25, 36, 49, 64, 81, 100]
2.2med Keep the evens

Task

Return a Vec<i32> of only the even values. Count your ampersands carefully.

Solution
Answer
fn evens(v: &[i32]) -> Vec<i32> {
    v.iter().filter(|&&x| x % 2 == 0).copied().collect()
}
// (1..=10) -> [2, 4, 6, 8, 10]
error[E0369]: cannot calculate the remainder of `&&{integer}`
              divided by `{integer}`
help: `%` can be used on `&{integer}` if you dereference the left-hand side
Why two ampersands

.iter() yields &i32, and filter lends the closure a reference to that — so you receive &&i32. Write |&&x| to strip both, or |x| **x % 2 == 0. Then .copied() converts the surviving &i32s to owned values.

2.3med Parse, skipping failures

Task

["1", "x", "3"] → [1, 3]. One adapter does both the filtering and the mapping.

Solution
Answer
fn parse_ok(v: &[&str]) -> Vec<i32> {
    v.iter().filter_map(|s| s.parse().ok()).collect()
}
// [1, 3]
Not filter + map

.filter(|s| s.parse::<i32>().is_ok()).map(|s| s.parse().unwrap()) parses everything twice and contains an unwrap. filter_map does it once, with none.

2.4med Filter then transform

Task

From ["apple", "fig", "banana", "kiwi"], uppercase only the words longer than 3 characters.

Solution
Answer
fn long_loud(v: &[&str]) -> Vec<String> {
    v.iter()
        .filter(|w| w.len() > 3)
        .map(|w| w.to_uppercase())
        .collect()
}
// ["APPLE", "BANANA", "KIWI"]

Note that .len() works through both references without a star — method calls auto-dereference where arithmetic does not.

2.5easy Change the type

Task

Turn [1, 2] into ["#1", "#2"] — numbers in, strings out.

Solution
Answer
fn tag_them(v: &[i32]) -> Vec<String> {
    v.iter().map(|x| format!("#{x}")).collect()
}
// ["#1", "#2"]

map can change the item type freely. Count in equals count out — that never changes.

2.6hard Drop the Nones

Task

[Some(1), None, Some(3)] → [1, 3]. There is a one-word adapter for this.

Solution
Answer
fn just_values(v: &[Option<i32>]) -> Vec<i32> {
    v.iter().flatten().copied().collect()
}
// [1, 3]
Option is an iterator

An Option is an iterator over zero or one item — Some(x) yields one, None yields none. So flatten collapses them and the Nones simply vanish. .filter_map(|x| *x) also works.

SET 03

Taking and skipping

3.1easy First n

Task

Return the first n elements.

Solution
Answer
fn first_n(v: &[i32], n: usize) -> Vec<i32> {
    v.iter().take(n).copied().collect()
}
// (1..=10) take 3 -> [1, 2, 3]

take asking for more than exists is fine — you get everything, with no panic.

3.2easy Drop the first n

Task

Return everything after the first n.

Solution
Answer
v.iter().skip(n).copied().collect()
// (1..=10) skip 7 -> [8, 9, 10]

.skip(1) is the idiomatic way to ignore a CSV header row.

3.3hard take_while is not filter

Task

On [1, 2, 3, 10, 1], use take_while(x < 5). Predict the result — then predict what filter(x < 5) would give instead.

take_while gives

filter would give

Solution
Answer
[1,2,3,10,1].iter().take_while(|&&x| x < 5)
// [1, 2, 3]        STOPS at 10 — never sees the final 1

[1,2,3,10,1].iter().filter(|&&x| x < 5)
// [1, 2, 3, 1]     checks EVERY item — keeps the final 1
The difference

take_while stops permanently at the first failure. filter tests everything. On sorted data they agree; on unsorted data they very much do not.

3.4med skip_while

Task

Same input, skip_while(x < 5). Why does the trailing 1 come through?

Solution
Answer
[1,2,3,10,1].iter().skip_while(|&&x| x < 5)
// [10, 1]

Once the condition first fails (at 10), skip_while stops testing entirely and passes everything remaining through — including values that would have failed. Useful for skipping a preamble.

3.5hard First n odd numbers, from infinity

Task

Return the first n odd numbers using the infinite range (1..). Two adapters.

Solution
Answer
fn odds(n: u32) -> Vec<u32> {
    (1..).step_by(2).take(n as usize).collect()
}
// n=5 -> [1, 3, 5, 7, 9]
The take is mandatory

Without it, collect() on an infinite range runs until memory is exhausted. Laziness makes infinite sources possible; a bound makes them safe.

3.6easy Reverse

Task

Return a reversed copy without touching the original.

Solution
Answer
v.iter().rev().copied().collect()
// [1,2,3] -> [3, 2, 1]

.rev() needs DoubleEndedIterator. Vectors, slices, and ranges have it; a HashMap iterator does not — there is no "back" to something with no order.

SET 04

Combining iterators

4.1med zip truncates

Task

Zip ["a", "b", "c"] with [1, 2]. How many pairs come out, and what happened to "c"?

Solution
Answer
a.iter().copied().zip(b.iter().copied()).collect()
// [("a", 1), ("b", 2)]     — only 2 pairs
Silent data loss

zip stops at the shorter iterator. "c" is dropped with no error and no warning. If the lengths should match, check before zipping.

4.2easy Concatenate

Task

Join [1, 2] and [3, 4] into one sequence.

Solution
Answer
a.iter().chain(b.iter()).copied().collect()
// [1, 2, 3, 4]
4.3easy Number a list

Task

["ada", "ravi"] → ["1. ada", "2. ravi"]. Note it starts at 1.

Solution
Answer
v.iter()
    .enumerate()
    .map(|(i, s)| format!("{}. {}", i + 1, s))
    .collect()
// ["1. ada", "2. ravi"]

enumerate is 0-based; the + 1 makes it human-facing. Destructure the tuple right in the closure parameter.

4.4med Flatten nested vectors

Task

[[1, 2], [3]] → [1, 2, 3].

Solution
Answer
v.iter().flatten().copied().collect()
// [1, 2, 3]

flatten removes exactly one level of nesting. Triple-nested needs it twice.

4.5med All characters from all strings

Task

["hi", "yo"] → ['h', 'i', 'y', 'o'].

Solution
Answer
v.iter().flat_map(|s| s.chars()).collect()
// ['h', 'i', 'y', 'o']
flat_map = map + flatten

With plain map you would get an iterator of Chars iterators — nested. flat_map maps and flattens in one step, which is what you almost always want when each item expands into many.

4.6hard Count words across lines

Task

Given ["hello world", "foo bar baz"], count the total words across all lines.

Solution
Answer
fn word_count(lines: &[&str]) -> usize {
    lines.iter()
        .flat_map(|l| l.split_whitespace())
        .count()
}
// 5

This is the real-world shape of flat_map: one line expands into many words, and you want them all in a single flat stream.

SET 05

Consumers

5.1easy Sum

Task

Total (1..=10).

Solution
Answer
v.iter().sum()      // 55
5.2med Factorial with product

Task

Compute 5! using product. Return i64 to leave headroom.

Solution
Answer
fn factorial(v: &[i32]) -> i64 {
    v.iter().map(|&x| x as i64).product()
}
// [1,2,3,4,5] -> 120

The map widens each value before multiplying — factorials overflow i32 quickly.

5.3easy Min and max

Task

Return both as (Option<i32>, Option<i32>). Why Option?

Solution
Answer
(v.iter().min().copied(), v.iter().max().copied())
// (1..=10) -> (Some(1), Some(10))

Option because an empty iterator has neither a minimum nor a maximum. The type forces you to handle that.

5.4med Reimplement sum with fold

Task

Write sum yourself using fold, to see what it is underneath.

Solution
Answer
v.iter().fold(0, |acc, x| acc + x)
// 55  — identical to .sum()

//         ↑ start   ↑ running total  ↑ current item

sum is fold(0, +); product is fold(1, *); count is fold(0, |a,_| a+1). Most consumers are folds in disguise.

5.5hard Build a string with fold

Task

Join ["a", "b", "c"] into "a-b-c" using fold — no separator on the first item.

Solution
Answer
v.iter().fold(String::new(), |mut acc, s| {
    if !acc.is_empty() { acc.push('-'); }
    acc.push_str(s);
    acc                     // must return the accumulator
})
// "a-b-c"
The accumulator can be any type

Here it is a String, not a number. Note |mut acc, s| and the bare acc at the end — you must hand the accumulator back each time. For this specific job .join("-") is clearer, but the pattern generalises to anything.

5.6med Average, safely

Task

Mean as f64. Empty input gives 0.0, not NaN.

Solution
Answer
fn mean(v: &[i32]) -> f64 {
    if v.is_empty() { return 0.0; }
    v.iter().sum::<i32>() as f64 / v.len() as f64
}
// [1,2,3,4] -> 2.5     [] -> 0.0

The turbofish on sum::<i32>() is needed because the as f64 gives the compiler nothing to infer from.

5.7hard Running totals

Task

[1,2,3,4,5] → [1, 3, 6, 10, 15]. fold gives only the final value — you need every step.

Solution
Answer
v.iter().scan(0, |acc, x| {
    *acc += x;
    Some(*acc)          // Some to continue, None to stop early
}).collect()
// [1, 3, 6, 10, 15]

scan is fold that yields every intermediate value. The state is &mut, hence the stars, and returning None ends the iterator early.

SET 06

Searching and testing

All of these short-circuit — they stop as soon as the answer is known.

6.1easy Does it contain?

Task

Return whether a value is present, using an iterator method.

Solution
Answer
v.iter().any(|&x| x == target)
// target 5 -> true,  target 99 -> false
Not filter().count() > 0

That scans everything. any stops at the first match — on a million items that is the difference between instant and slow.

6.2easy Are they all positive?

Task

Return true only if every element is greater than zero.

Solution
Answer
v.iter().all(|&x| x > 0)
// (1..=10) -> true     [1, -1] -> false

On an empty iterator all returns true and any returns false. That is the mathematically standard convention, and it occasionally surprises people.

6.3med find vs position

Task

On (1..=10): get the first value greater than 5, and separately the index of the value 5. Note what each returns.

Solution
Answer
v.iter().find(|&&x| x > 5).copied()    // Some(6)  — the VALUE
v.iter().position(|&x| x == 5)          // Some(4)  — the INDEX

find gives you the item, position gives you where it was. Note the different closure signatures: find gets &&T, position gets &T.

6.4easy Index of a value

Task

Return the index of the first occurrence of a target, or None.

Solution
Answer
fn index_of(v: &[i32], t: i32) -> Option<usize> {
    v.iter().position(|&x| x == t)
}
// value 5 in (1..=10) -> Some(4)
6.5med Longest string

Task

From ["aa", "b", "ccc"], return the longest.

Solution
Answer
v.iter().max_by_key(|s| s.len()).copied()
// Some("ccc")
Ties

max_by_key returns the last maximum on a tie; min_by_key returns the first. If that matters, sort with an explicit tie-break instead.

6.6hard Smallest float

Task

Find the minimum of [3.5, 1.2, 9.9]. Plain .min() will not compile — why, and what is the fix?

Solution
Answer
v.iter().copied().min_by(|a, b| a.partial_cmp(b).unwrap())
// Some(1.2)
The NaN problem again

.min() requires Ord. f64 only has PartialOrd, because NaN compares false against everything — including itself — so no total order exists. Same reason .sort() fails on floats. Use .total_cmp() instead of partial_cmp().unwrap() if NaN is genuinely possible.

SET 07

collect targets

The same call builds wildly different things, decided entirely by the type you ask for.

7.1easy Collect into a HashSet

Task

Deduplicate [3, 1, 3, 2] by collecting into a set.

Solution
Answer
use std::collections::HashSet;

fn unique(v: &[i32]) -> HashSet<i32> {
    v.iter().copied().collect()
}
// sorted for display: [1, 2, 3]

The return type is the entire instruction — collect reads it and builds accordingly.

7.2med Collect into a HashMap

Task

Zip keys and values into a map in one expression.

Solution
Answer
keys.iter().copied()
    .zip(vals.iter().copied())
    .collect()
// len = 2

Any iterator of (K, V) pairs collects into a HashMap — or a BTreeMap if you ask for that instead.

7.3easy Chars into a String

Task

['h', 'i'] → "hi".

Solution
Answer
fn to_text(v: &[char]) -> String {
    v.iter().collect()
}
// "hi"

// This is how you reverse a string:
// let r: String = "abc".chars().rev().collect();   // "cba"
7.4hard Collect into a Result

Task

Parse every string, failing entirely if any one fails. Contrast with exercise 2.3, which skipped failures.

Solution
Answer
fn parse_all(v: &[&str]) -> Result<Vec<i32>, std::num::ParseIntError> {
    v.iter().map(|s| s.parse::<i32>()).collect()
}
// ["1","2"] -> Ok([1, 2])
// ["1","x"] -> Err(...)   and it STOPPED at "x"
A real design decision

An iterator of Results collects into a Result of a collection. filter_map(.. .ok()) means "skip the bad ones"; this means "fail if any is bad". Both are one line — choosing between them is about how strict your program should be.

7.5med Partition

Task

Split [1..6] into evens and odds in a single pass.

Solution
Answer
fn split_parity(v: &[i32]) -> (Vec<i32>, Vec<i32>) {
    v.iter().partition(|&&x| x % 2 == 0)
}
// ([2, 4, 6], [1, 3, 5])

Matching items go left, the rest go right. Better than filtering twice — one pass, both halves.

7.6med Unzip

Task

[(1,'a'), (2,'b')] → ([1,2], ['a','b']).

Solution
Answer
fn split_pairs(v: Vec<(i32, char)>) -> (Vec<i32>, Vec<char>) {
    v.into_iter().unzip()
}
// ([1, 2], ['a', 'b'])

Exactly the inverse of zip.

SET 08

Writing your own iterators

Implement next(), inherit seventy-five methods.

8.1hard A countdown iterator

Task

Write Countdown { n } that yields n, n-1, ... 1 then stops. Implement Iterator for it.

Solution
Answer
struct Countdown { n: u32 }

impl Iterator for Countdown {
    type Item = u32;

    fn next(&mut self) -> Option<u32> {
        if self.n == 0 {
            None
        } else {
            self.n -= 1;
            Some(self.n + 1)
        }
    }
}

Countdown { n: 5 }.collect::<Vec<_>>()   // [5, 4, 3, 2, 1]
You now have everything

With next() written, Countdown gets map, filter, zip, sum, take and the rest for free — that is the required-method/default-method pattern from traits, at its most dramatic.

8.2hard An infinite iterator

Task

Write Doubling, starting at 1 and doubling forever. Take the first 8. What must never be missing from the call site?

Solution
Answer
struct Doubling { cur: u64 }

impl Iterator for Doubling {
    type Item = u64;
    fn next(&mut self) -> Option<u64> {
        let r = self.cur;
        self.cur *= 2;
        Some(r)              // never None — infinite
    }
}

Doubling { cur: 1 }.take(8).collect::<Vec<_>>()
// [1, 2, 4, 8, 16, 32, 64, 128]
The take is not optional

Without it, collect() loops until memory runs out. Any infinite iterator must meet a take, take_while, find, or any somewhere in the chain.

8.3hard IntoIterator for your own type

Task

Given Bag { items: Vec<String> }, implement IntoIterator twice — once for Bag (owned) and once for &Bag (borrowed) — so both for x in bag and for x in &bag work.

Solution
Answer
struct Bag { items: Vec<String> }

// BY VALUE — consumes the Bag
impl IntoIterator for Bag {
    type Item = String;
    type IntoIter = std::vec::IntoIter<String>;
    fn into_iter(self) -> Self::IntoIter {
        self.items.into_iter()
    }
}

// BY REFERENCE — what `for x in &bag` uses
impl<'a> IntoIterator for &'a Bag {
    type Item = &'a String;
    type IntoIter = std::slice::Iter<'a, String>;
    fn into_iter(self) -> Self::IntoIter {
        self.items.iter()
    }
}

// borrowed = ["x", "y"] — bag still usable
// owned    = ["x", "y"] — bag consumed

This is exactly how Vec supports all three for forms — three separate trait impls, nothing special-cased in the language.

8.4hard Accept anything iterable

Task

Write a total function that accepts a Vec, a range, an array — anything yielding i32.

Solution
Answer
fn total<I>(items: I) -> i32
where
    I: IntoIterator<Item = i32>,
{
    items.into_iter().sum()
}

total(vec![1, 2, 3]);   // 6
total(1..=3);           // 6  — same function

Note Item = i32 with an equals sign — associated-type syntax. Taking IntoIterator is the most flexible parameter you can accept.

8.5med Generate without a struct

Task

Produce powers of 3 — [1, 3, 9, 27, 81] — using std::iter::successors, with no custom type.

Solution
Answer
fn powers_of_three(n: usize) -> Vec<u32> {
    std::iter::successors(Some(1u32), |&x| Some(x * 3))
        .take(n)
        .collect()
}
// [1, 3, 9, 27, 81]

Each item is computed from the previous. For throwaway sequences this saves defining a struct; use a real Iterator impl when the type needs a name.

FINAL

Capstone: a log analyser

Everything at once. Parse and analyse a log using only iterator chains — no manual index loops anywhere.

Given
#[derive(Debug, Clone)]
struct LogLine {
    level:  String,   // INFO / WARN / ERROR
    module: String,
    ms:     u32,
}

// Raw input — note the final line is malformed on purpose:
// INFO  | auth | 12
// ERROR | db   | 340
// INFO  | api  | 8
// ERROR | db   | 55
// WARN  | api  | 200
// bad line
C.1hard parse_log — skip malformed lines

Task

Turn the raw text into Vec<LogLine>, silently dropping any line that is not three |-separated fields with a numeric duration.

Solution
Answer
fn parse_log(raw: &str) -> Vec<LogLine> {
    raw.lines()
        .filter_map(|l| {
            let parts: Vec<&str> = l.split('|').map(|p| p.trim()).collect();
            if parts.len() != 3 { return None; }
            let ms = parts[2].parse().ok()?;      // ? inside the closure
            Some(LogLine {
                level:  parts[0].to_string(),
                module: parts[1].to_string(),
                ms,
            })
        })
        .collect()
}
// parsed = 5   (the "bad line" was dropped)
Why filter_map

Each line either produces a LogLine or nothing — exactly what filter_map is for. The ? works inside the closure because the closure returns Option, so a failed parse becomes None and that line is skipped.

C.2med count_by_level

Task

Return HashMap<String, usize> counting lines per level.

Solution
Answer
fn count_by_level(logs: &[LogLine]) -> HashMap<String, usize> {
    let mut m = HashMap::new();
    for l in logs {
        *m.entry(l.level.clone()).or_insert(0) += 1;
    }
    m
}
// sorted: [("ERROR", 2), ("INFO", 2), ("WARN", 1)]

The counting idiom from the HashMap topic, fed by an iterator. Sorted here only for display — map order is arbitrary.

C.3med slowest

Task

Return the slowest log line as Option<&LogLine>.

Solution
Answer
fn slowest(logs: &[LogLine]) -> Option<&LogLine> {
    logs.iter().max_by_key(|l| l.ms)
}
// Some(("db", 340))

ms is u32, which implements Ord, so max_by_key works directly. Had it been f64 you would need max_by with partial_cmp.

C.4med total_ms_of a level

Task

Sum the durations of all lines at a given level. Filter, extract, add.

Solution
Answer
fn total_ms_of(logs: &[LogLine], level: &str) -> u32 {
    logs.iter()
        .filter(|l| l.level == level)
        .map(|l| l.ms)
        .sum()
}
// "ERROR" -> 395     (340 + 55)

The canonical three-stage chain: narrow the set, extract one field, reduce to a number.

C.5hard modules_touched

Task

Return every distinct module name, sorted. Note that db and api each appear twice.

Solution
Answer
fn modules_touched(logs: &[LogLine]) -> Vec<String> {
    let s: HashSet<&str> = logs.iter()
        .map(|l| l.module.as_str())
        .collect();
    let mut v: Vec<String> = s.into_iter().map(|x| x.to_string()).collect();
    v.sort();
    v
}
// ["api", "auth", "db"]

Collecting into a HashSet deduplicates for free. The sort at the end is required — sets have no order.

C.6hard slow_errors — the full pipeline

Task

Return formatted strings for every ERROR slower than a threshold: "module (Nms)". Two conditions, then a format.

Solution
Answer
fn slow_errors(logs: &[LogLine], threshold: u32) -> Vec<String> {
    logs.iter()
        .filter(|l| l.level == "ERROR" && l.ms > threshold)
        .map(|l| format!("{} ({}ms)", l.module, l.ms))
        .collect()
}
// threshold 100 -> ["db (340ms)"]
// the 55ms ERROR is below threshold; the 200ms WARN is the wrong level
Reading it back

Take the logs, keep the slow errors, format each one, gather them up. Four lines that say exactly what they do — and the compiler turns them into a single pass with no intermediate allocation.
