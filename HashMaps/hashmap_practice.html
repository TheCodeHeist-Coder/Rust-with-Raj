SET 01

Creating and reading

The basics, plus the safe-versus-panicking read you already know from vectors.

1.1easy Build a map from scratch

Task

Return a HashMap<String, i32> with "ada" → 90 and "ravi" → 78.

Solution
Answer
use std::collections::HashMap;

fn make_scores() -> HashMap<String, i32> {
    let mut m = HashMap::new();
    m.insert("ada".to_string(), 90);
    m.insert("ravi".to_string(), 78);
    m
}
// keys, sorted: ["ada", "ravi"]

mut is required to insert. The trailing m with no semicolon returns it. HashMap::new() needs no annotation here because the return type pins K and V.

1.2easy From an array of pairs

Task

Build a map with a→1, b→2, c→3 in a single expression — no mut, no loop.

Solution
Answer
let m = HashMap::from([("a", 1), ("b", 2), ("c", 3)]);
// len = 3

There is no hashmap! macro in std. HashMap::from([...]) is the idiomatic literal form.

1.3med Zip two slices into a map

Task

Given names ["x", "y"] and values [1, 2], build a map pairing them.

Solution
Answer
fn zip_map(names: &[&'static str], vals: &[i32])
    -> HashMap<&'static str, i32>
{
    names.iter().copied()
        .zip(vals.iter().copied())
        .collect()
}
// len = 2

collect() builds a HashMap from any iterator of (K, V) pairs — the same collect you used for vectors, steered by the return type.

1.4easy Read with a default

Task

Return the value for a key, or 0 if it is missing. Must never panic.

Solution
Answer
fn get_or_zero(m: &HashMap<&str, i32>, k: &str) -> i32 {
    m.get(k).copied().unwrap_or(0)
}
// present -> 1,  missing -> 0
Not this

m[k] panics with no entry found for key. It compiles fine — the failure only shows up at runtime.

1.5med Match on a lookup

Task

Return "k = v" if the key exists, or "k not found" if not. Use match.

Solution
Answer
fn describe(m: &HashMap<&str, i32>, k: &str) -> String {
    match m.get(k) {
        Some(v) => format!("{k} = {v}"),
        None    => format!("{k} not found"),
    }
}
// "a = 1"  |  "zz not found"
SET 02

Insert, update, remove

2.1med What does insert return?

Task

Insert the same key twice with different values. Write down what each call returns before running it.

First insert returns

Second insert returns

Solution
Answer
let mut m: HashMap<String, i32> = HashMap::new();

m.insert("a".to_string(), 1);   // None     — key was new
m.insert("a".to_string(), 2);   // Some(1)  — replaced, old value returned
Why it matters

Keys are unique — the second insert overwrites silently, with no error. The returned Option is how you detect that it happened, which is useful for "was this already set?" checks.

2.2easy Remove a key twice

Task

Remove the same key twice. What comes back each time?

Solution
Answer
let mut m = HashMap::from([("a", 1), ("b", 2)]);

m.remove("a");   // Some(1)  — removed, handed back
m.remove("a");   // None     — already gone, no panic

Like Vec::pop, the Option means the "not there" case needs no special handling.

2.3med Modify a value in place

Task

Add delta to the value at a key, doing nothing if the key is absent. Use get_mut.

Solution
Answer
fn bump(m: &mut HashMap<&str, i32>, k: &str, delta: i32) {
    if let Some(v) = m.get_mut(k) {
        *v += delta;      // * — v is &mut i32
    }
}
// 10 with delta 5 -> Some(15)
Not m[k] += delta

HashMap has no IndexMut, so assigning through an index does not compile — E0594. Use get_mut or the entry API.

2.4med Keep only even keys

Task

From a map keyed 1–6, keep only the pairs whose key is even.

Solution
Answer
fn keep_even(m: &mut HashMap<i32, i32>) {
    m.retain(|k, _| k % 2 == 0);
}
// keys left: [2, 4, 6]

Same retain as Vec, but the closure gets both key and value — |k, v|. Use _ for the one you ignore.

2.5easy Double every value

Task

Multiply every value in the map by 2, in place.

Solution
Answer
fn double_all(m: &mut HashMap<&str, i32>) {
    for v in m.values_mut() {
        *v *= 2;
    }
}
// values 1, 2 -> 2, 4

values_mut() when you only touch values. Note there is no keys_mut() — changing a key would change its hash and corrupt the map.

SET 03

The entry API

The most important set in this workbook. Do all five, even if the first two feel easy — the idiom needs to become automatic.

3.1med Character frequency

Task

Count how often each character appears in "hello world", ignoring spaces.

Solution
Answer
fn char_counts(text: &str) -> HashMap<char, i32> {
    let mut counts = HashMap::new();
    for c in text.chars().filter(|c| !c.is_whitespace()) {
        *counts.entry(c).or_insert(0) += 1;
    }
    counts
}
// sorted: [('d',1), ('e',1), ('h',1), ('l',3), ('o',2), ('r',1), ('w',1)]
Reading the line

entry(c) gets a handle to that slot. or_insert(0) puts a 0 there if empty and returns &mut i32 either way. The leading * reaches through that reference so += 1 works on the number.

3.2med Word frequency

Task

Count occurrences in ["a", "b", "a", "c", "a"], returning a HashMap<String, i32>.

Solution
Answer
fn word_counts(words: &[&str]) -> HashMap<String, i32> {
    let mut counts = HashMap::new();
    for w in words {
        *counts.entry(w.to_string()).or_insert(0) += 1;
    }
    counts
}
// sorted: [("a", 3), ("b", 1), ("c", 1)]

Identical shape to 3.1. The to_string() is needed because the map owns String keys.

3.3hard Group words by length

Task

Group ["hi", "hey", "hello", "yo"] into a HashMap<usize, Vec<&str>> keyed by length.

Solution
Answer
fn by_length<'a>(words: &[&'a str]) -> HashMap<usize, Vec<&'a str>> {
    let mut groups: HashMap<usize, Vec<&str>> = HashMap::new();
    for w in words {
        groups.entry(w.len()).or_insert_with(Vec::new).push(w);
    }
    groups
}
// sorted: [(2, ["hi", "yo"]), (3, ["hey"]), (5, ["hello"])]
or_insert_with, not or_insert

or_insert(Vec::new()) would build a fresh empty Vec on every iteration and discard it whenever the key already exists. or_insert_with(Vec::new) only calls it when needed. Note: no () — you pass the function, not its result.

3.4hard and_modify vs or_insert

Task

Write a function that inserts 1 for a new key, but adds 1 to an existing one. Call it three times on the same key — what is the final value?

Solution
Answer
fn tally(m: &mut HashMap<&'static str, i32>, k: &'static str) {
    m.entry(k).and_modify(|v| *v += 1).or_insert(1);
}
// three calls on "x" -> Some(3)
//   1st: absent  -> or_insert(1)  = 1
//   2nd: present -> and_modify    = 2
//   3rd: present -> and_modify    = 3

and_modify runs only when the key exists; or_insert only when it does not. Chaining them gives different behaviour for the two cases in one expression.

3.5hard Partition into even and odd

Task

Split [1..6] into a HashMap<bool, Vec<i32>> where the key is "is even". Use or_default().

Solution
Answer
fn split_parity(nums: &[i32]) -> HashMap<bool, Vec<i32>> {
    let mut g: HashMap<bool, Vec<i32>> = HashMap::new();
    for &n in nums {
        g.entry(n % 2 == 0).or_default().push(n);
    }
    g
}
// true  -> [2, 4, 6]
// false -> [1, 3, 5]

or_default() uses the type's Default impl — an empty Vec here. It is the shortest form when the default is the obvious one.

SET 04

Iteration

Every exercise here sorts before returning — map order is arbitrary, so unsorted output is untestable.

4.1easy Sum all values

Task

Total every value in the map.

Solution
Answer
fn total(m: &HashMap<&str, i32>) -> i32 {
    m.values().sum()
}
// {ada:90, ravi:78, meera:88} -> 256
4.2easy Sorted keys

Task

Return every key as a sorted Vec<String>.

Solution
Answer
fn sorted_keys(m: &HashMap<&str, i32>) -> Vec<String> {
    let mut k: Vec<String> = m.keys().map(|s| s.to_string()).collect();
    k.sort();
    k
}
// ["ada", "meera", "ravi"]
The sort is mandatory

Without it the order differs between runs of the same binary — Rust randomises the hash seed at startup. Tests that skip this pass locally and fail in CI.

4.3med Filter by value

Task

Return the names of everyone scoring above a threshold, sorted.

Solution
Answer
fn above<'a>(m: &HashMap<&'a str, i32>, min: i32) -> Vec<&'a str> {
    let mut v: Vec<&str> = m.iter()
        .filter(|(_, &s)| s > min)
        .map(|(k, _)| *k)
        .collect();
    v.sort();
    v
}
// min 80 -> ["ada", "meera"]

The closure receives a (&K, &V) tuple. |(_, &s)| ignores the key and destructures the value reference in one step.

4.4med Highest scorer

Task

Return the key–value pair with the largest value, as an Option.

Solution
Answer
fn top(m: &HashMap<&str, i32>) -> Option<(String, i32)> {
    m.iter()
        .max_by_key(|(_, &v)| v)
        .map(|(k, &v)| (k.to_string(), v))
}
// Some(("ada", 90))
Ties are unpredictable

If two keys share the maximum value, which one you get is arbitrary — the map has no order. Only rely on this when the maximum is unique, or sort explicitly to break ties.

4.5hard A leaderboard

Task

Return all pairs sorted by value descending, breaking ties by key ascending.

Solution
Answer
fn leaderboard(m: &HashMap<&str, i32>) -> Vec<(String, i32)> {
    let mut v: Vec<(String, i32)> = m.iter()
        .map(|(k, &s)| (k.to_string(), s))
        .collect();
    v.sort_by(|a, b| b.1.cmp(&a.1).then(a.0.cmp(&b.0)));
    v
}
// [("ada", 90), ("meera", 88), ("ravi", 78)]
.then() for tie-breaking

b.1.cmp(&a.1) sorts by value descending. .then(...) supplies a second comparison used only when the first says Equal. Chaining then gives you multi-level sorting, and it makes the result deterministic even with ties.

4.6med Invert a map

Task

Swap keys and values: HashMap<&str, i32> becomes HashMap<i32, String>. What breaks if two keys share a value?

Solution
Answer
fn invert(m: &HashMap<&str, i32>) -> HashMap<i32, String> {
    m.iter().map(|(k, &v)| (v, k.to_string())).collect()
}
// len = 3 when all values are distinct
Duplicate values collapse

If two names share a score, they collide on the same new key and one silently overwrites the other — the result is smaller than the input. If that matters, invert into HashMap<i32, Vec<String>> using the grouping idiom instead.

SET 05

HashSet basics

Remember insert returns a bool — several of these depend on it.

5.1easy Deduplicate a vector

Task

Turn [3, 1, 3, 2, 1] into a sorted vector of unique values, using a HashSet.

Solution
Answer
use std::collections::HashSet;

fn unique(v: &[i32]) -> Vec<i32> {
    let s: HashSet<i32> = v.iter().copied().collect();
    let mut out: Vec<i32> = s.into_iter().collect();
    out.sort();
    out
}
// [1, 2, 3]

Compare with vec.sort() + vec.dedup() from the vectors topic — that keeps order and needs Ord; this is O(n) and needs Hash + Eq.

5.2hard Deduplicate, keeping first-seen order

Task

["a", "b", "a", "c"] → ["a", "b", "c"], preserving the original order. Collecting straight into a set will not work — why not?

Solution
Answer
fn dedup_ordered(v: &[&str]) -> Vec<String> {
    let mut seen = HashSet::new();
    v.iter()
        .filter(|s| seen.insert(s.to_string()))
        .map(|s| s.to_string())
        .collect()
}
// ["a", "b", "c"]
The trick

insert returns true only the first time it sees a value. So filter keeps first occurrences and the set records them in the same step. Collecting directly into a HashSet would work but destroy the order — sets have none.

5.3med Any duplicates?

Task

Return true if the slice contains any repeated value. Stop early when you find one.

Solution
Answer
fn has_dupes(v: &[i32]) -> bool {
    let mut s = HashSet::new();
    v.iter().any(|x| !s.insert(x))
}
// [1,2,3] -> false
// [1,2,1] -> true

any short-circuits on the first true, so this stops at the first duplicate rather than scanning everything.

5.4hard Which values repeat?

Task

From [1, 2, 2, 3, 3, 3] return the sorted values that appear more than once — each listed once.

Solution
Answer
fn repeated(v: &[i32]) -> Vec<i32> {
    let mut seen = HashSet::new();
    let mut dupes = HashSet::new();
    for &x in v {
        if !seen.insert(x) {
            dupes.insert(x);      // second set dedupes the dupes
        }
    }
    let mut out: Vec<i32> = dupes.into_iter().collect();
    out.sort();
    out
}
// [2, 3]   — 3 appears three times but is listed once

Two sets: one tracking what has been seen, one collecting offenders. The second is what stops 3 appearing twice in the output.

SET 06

Set operations

All exercises use a = {1,2,3,4} and b = {3,4,5,6}. Results are sorted for comparison.

6.1easy Intersection

Task

Return the values present in both sets.

Solution
Answer
fn both(a: &HashSet<i32>, b: &HashSet<i32>) -> Vec<i32> {
    let mut v: Vec<i32> = a.intersection(b).copied().collect();
    v.sort();
    v
}
// [3, 4]

These methods return iterators, not sets — you must collect to use the result.

6.2easy Union

Task

Return everything in either set, with no duplicates.

Solution
Answer
let mut v: Vec<i32> = a.union(b).copied().collect();
v.sort();
// [1, 2, 3, 4, 5, 6]
6.3med Difference

Task

Return what is in a but not b. Then swap the arguments — do you get the same answer?

Solution
Answer
let mut v: Vec<i32> = a.difference(b).copied().collect();
v.sort();
// a.difference(b) = [1, 2]     in a, not in b
// b.difference(a) = [5, 6]     DIFFERENT — it is directional

Difference is the only one of the four that is not symmetric. Intersection, union, and symmetric difference give the same answer either way round.

6.4med Symmetric difference

Task

Return the values in exactly one of the two sets.

Solution
Answer
let mut v: Vec<i32> = a.symmetric_difference(b).copied().collect();
v.sort();
// [1, 2, 5, 6]   — everything except the shared 3 and 4

Equivalent to union minus intersection, but in one pass.

6.5med A permission check

Task

Given required permissions and granted permissions, return whether the user has everything they need. One method call.

Solution
Answer
fn allowed(required: &HashSet<&str>, granted: &HashSet<&str>) -> bool {
    required.is_subset(granted)
}
// required {read}, granted {read, write} -> true

This is the kind of thing sets are for. The alternative — looping over required and checking each against granted — is five lines that say less clearly.

6.6hard Diff two lists

Task

Given an old and a new set of ids, return (added, removed) — both sorted.

Solution
Answer
fn diff<'a>(old: &HashSet<&'a str>, new: &HashSet<&'a str>)
    -> (Vec<&'a str>, Vec<&'a str>)
{
    let mut added:   Vec<&str> = new.difference(old).copied().collect();
    let mut removed: Vec<&str> = old.difference(new).copied().collect();
    added.sort();
    removed.sort();
    (added, removed)
}
// old {a,b}, new {b,c} -> (["c"], ["a"])
Direction is the whole trick

new.difference(old) = things in new that were not in old = additions. Reverse it for removals. Getting these backwards is the classic bug — and it compiles perfectly.

SET 07

Custom keys and structs

7.1hard Make a struct usable as a key

Task

This does not compile. Read the error, then fix it — and write down which two traits are missing and why each is needed.

Broken
#[derive(Debug)]
struct Point { x: i32, y: i32 }

let mut m: HashMap<Point, String> = HashMap::new();
m.insert(Point { x: 0, y: 0 }, "origin".to_string());

Missing traits, and why

Solution
error[E0599]: the method `insert` exists for struct
              `HashMap<Point, String>`, but its trait bounds
              were not satisfied
  |
  | struct Point { x: i32, y: i32 }
  | ------------ doesn't satisfy `Point: Eq` or `Point: Hash`
help: consider annotating `Point` with `#[derive(Eq, Hash, PartialEq)]`
Fixed
#[derive(Debug, PartialEq, Eq, Hash)]
struct Point { x: i32, y: i32 }
// now len = 2 after two inserts
Why these two

Hash turns the key into a number so the map knows which bucket to use. Eq settles which key is which when two land in the same bucket. Both are required; neither is enough alone. Eq also requires PartialEq, which is why all three appear.

7.2med Group employees by department

Task

Given Employee { name, dept, salary }, build HashMap<String, Vec<String>> mapping department to employee names.

Solution
Answer
fn by_dept(emps: &[Employee]) -> HashMap<String, Vec<String>> {
    let mut g: HashMap<String, Vec<String>> = HashMap::new();
    for e in emps {
        g.entry(e.dept.clone())
            .or_insert_with(Vec::new)
            .push(e.name.clone());
    }
    g
}
// [("Eng", ["Ada", "Ravi"]), ("Sales", ["Meera"])]

The grouping idiom again. Both clone()s are needed because the map owns its keys and values while emps is only borrowed.

7.3hard Average salary per department

Task

Return HashMap<String, f64> of mean salary by department. You need a running sum and a count per department.

Solution
Answer
fn avg_by_dept(emps: &[Employee]) -> HashMap<String, f64> {
    // accumulate (total, count) per department
    let mut sums: HashMap<String, (u32, u32)> = HashMap::new();
    for e in emps {
        let t = sums.entry(e.dept.clone()).or_insert((0, 0));
        t.0 += e.salary;
        t.1 += 1;
    }
    // then divide
    sums.into_iter()
        .map(|(d, (total, n))| (d, total as f64 / n as f64))
        .collect()
}
// [("Eng", 95.0), ("Sales", 80.0)]
A tuple as the value

Storing (sum, count) lets one pass gather everything needed. or_insert((0,0)) returns &mut (u32,u32), and t.0/t.1 modify the tuple fields through it — no dereference star needed, because field access auto-dereferences.

7.4med Highest paid

Task

Return the highest-paid employee as Option<&Employee>.

Solution
Answer
fn highest_paid(emps: &[Employee]) -> Option<&Employee> {
    emps.iter().max_by_key(|e| e.salary)
}
// Some("Ada")

max_by_key works directly because salary is u32, which implements Ord. Had it been f64 you would need max_by with partial_cmp, as in the vectors workbook.

SET 08

BTreeMap

Same interface, permanently sorted by key.

8.1med Convert HashMap to BTreeMap

Task

Turn a HashMap<&str, i32> into a BTreeMap<String, i32> and iterate it. What is different about the output?

Solution
Answer
use std::collections::BTreeMap;

fn to_btree(m: &HashMap<&str, i32>) -> BTreeMap<String, i32> {
    m.iter().map(|(k, &v)| (k.to_string(), v)).collect()
}
// [("ada", 90), ("meera", 88), ("ravi", 78)]
// Sorted — and sorted on EVERY run, with no sort() call.

Same collect, different destination type. If you find yourself sorting a map every time you touch it, this is the better structure.

8.2easy Keys come out sorted

Task

Return the keys of a BTreeMap. Notice what you do not have to write.

Solution
Answer
fn keys_of(b: &BTreeMap<String, i32>) -> Vec<String> {
    b.keys().cloned().collect()      // no .sort() needed
}
// ["ada", "meera", "ravi"]

Compare with exercise 4.2, where the sort() was mandatory. That is the entire trade: O(log n) lookups in exchange for never sorting again.

8.3med Smallest key

Task

Return the pair with the smallest key. Why is this cheap on a BTreeMap but not on a HashMap?

Solution
Answer
fn smallest(b: &BTreeMap<i32, &str>) -> Option<(i32, String)> {
    b.iter().next().map(|(&k, &v)| (k, v.to_string()))
}
// Some((1, "a"))

// BTreeMap also has first_key_value() / last_key_value().

Because a BTreeMap is ordered, the first item is the smallest — one step. On a HashMap you would have to scan every entry, since there is no order to exploit.

FINAL

Capstone: a word frequency analyser

Everything at once. Build a small text analyser backed by a HashMap<String, usize>, using this test input:

Given
use std::collections::{HashMap, HashSet};

struct WordStats {
    counts: HashMap<String, usize>,
}

// Test text:
// "the quick brown fox the lazy dog the end"
C.1hard new — build the counts

Task

Write new(text). Split on whitespace, strip non-alphanumeric characters, lowercase everything, and skip anything that ends up empty.

Solution
Answer
impl WordStats {
    fn new(text: &str) -> Self {
        let mut counts: HashMap<String, usize> = HashMap::new();
        for w in text.split_whitespace() {
            let clean: String = w.chars()
                .filter(|c| c.is_alphanumeric())
                .collect::<String>()
                .to_lowercase();
            if !clean.is_empty() {
                *counts.entry(clean).or_insert(0) += 1;
            }
        }
        WordStats { counts }
    }
}

The cleaning step matters: without it "dog." and "dog" count as different words. The is_empty guard stops a token of pure punctuation becoming an empty-string key.

C.2med total_words, unique_words, count_of

Task

  • total_words() — every word, including repeats
  • unique_words() — distinct words only
  • count_of(w) — occurrences of one word, 0 if absent
Solution
Answer
    fn total_words(&self) -> usize {
        self.counts.values().sum()      // sum of counts
    }

    fn unique_words(&self) -> usize {
        self.counts.len()               // number of keys
    }

    fn count_of(&self, w: &str) -> usize {
        self.counts.get(w).copied().unwrap_or(0)
    }
Verified output
total=9  unique=7
count_of("the")=3   count_of("zzz")=0

The distinction is the point: 9 words were written, but only 7 different ones — because "the" appears three times.

C.3hard top_n — most frequent words

Task

Return the n most frequent words as Vec<(String, usize)>, highest first. Ties must break alphabetically so the result is deterministic.

Solution
Answer
    fn top_n(&self, n: usize) -> Vec<(String, usize)> {
        let mut v: Vec<(String, usize)> = self.counts
            .iter()
            .map(|(k, &c)| (k.clone(), c))
            .collect();
        v.sort_by(|a, b| b.1.cmp(&a.1).then(a.0.cmp(&b.0)));
        v.into_iter().take(n).collect()
    }
Verified output
top_n(3) = [("the", 3), ("brown", 1), ("dog", 1)]
Why the tie-break is not optional

Six words tie at count 1. Without .then(a.0.cmp(&b.0)) you would get an arbitrary three of them, differing between runs. The alphabetical tie-break is what makes "brown" and "dog" the reproducible answer.

C.4med words_appearing_once

Task

Return every word that appears exactly once, sorted alphabetically.

Solution
Answer
    fn words_appearing_once(&self) -> Vec<String> {
        let mut v: Vec<String> = self.counts
            .iter()
            .filter(|(_, &c)| c == 1)
            .map(|(k, _)| k.clone())
            .collect();
        v.sort();
        v
    }
Verified output
["brown", "dog", "end", "fox", "lazy", "quick"]

Six of the seven unique words appear once — everything except "the".

C.5hard shared_with — vocabulary overlap

Task

Given another WordStats, return the words that appear in both texts, sorted. This is where HashSet earns its place.

Solution
Answer
    fn shared_with(&self, other: &WordStats) -> Vec<String> {
        let a: HashSet<&String> = self.counts.keys().collect();
        let b: HashSet<&String> = other.counts.keys().collect();

        let mut v: Vec<String> = a.intersection(&b)
            .map(|s| (*s).clone())
            .collect();
        v.sort();
        v
    }
Verified output
text A: "the quick brown fox the lazy dog the end"
